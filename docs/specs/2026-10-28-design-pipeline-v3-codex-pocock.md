# design-pipeline v3: Codex и конвейер Покока

**Дата:** 2026-10-28
**Статус:** принято Анатолём, реализовано в 0.2.0.

## Почему

1. В стеке появился Codex. Конвейер был написан под Claude Code: синтаксис `/impeccable`,
   правило в `CLAUDE.md`, проверка только `~/.claude/skills`.
2. Superpowers заменён конвейером Matt Pocock skills. У Покока процессные скиллы
   (`implement`, `to-tickets`, `code-review`) user-invoked и зовут другие скиллы явно по имени.
   Схема v2 «design-pipeline подхватится по description внутри флоу» тут ненадёжна.
3. impeccable ушёл с 2.x на 4.8.0: `teach` заменён на `init`, `extract` больше не тянет токены
   с чужого URL, появился CLI-детектор `npx impeccable detect`.

## Решения

| Вопрос | Решение | Отвергнуто |
|---|---|---|
| Глубина интеграции с Пококом | фазы по стадиям: grill → to-spec → to-tickets → implement → code-review | отдельная труба со ссылкой в правиле |
| Референс без extract-по-URL | Pocock `prototype` (UI-ветка, N вариантов) + референс вводной в `impeccable shape`, победитель через `document` | ждать, вдруг в 4.x есть путь «токены с URL» |
| Как не потерять дизайн-систему в тикетах | тикет «Дизайн-система» первым, нативно блокирует все UI-тикеты (prefactor) | дизайн-шаг внутри каждого тикета |
| Ревью | третья ось Design после `code-review`, начинается с детерминированного `detect` | правка Pocock `code-review` (апстрим перезаписывает скиллы при синке) |
| Codex | один скилл на оба харнеса, `agents/openai.yaml`, таблица синтаксиса | отдельный форк под Codex |

## Не трогаем

Pocock-скиллы не правятся: связка живёт в design-pipeline и в одном правиле в `CLAUDE.md` /
`AGENTS.md`. Иначе каждый синк апстрима будет её сносить.

## Отвергнуто: shadcn/ui (2026-10-28)

Пробовали встроить shadcn как компонентный слой. Отказались: основная работа ведётся над
сайтами на Astro, а shadcn даёт пользу в приложениях (формы, таблицы, диалоги). На сайте его
интерактивные компоненты требуют React и Radix на публичных страницах, а единый стиль и анти-slop
уже закрывает impeccable. Доказательство из практики: в ATELIER shadcn стоял с мая, и ни один
компонент не был импортирован. Для React-приложений (CRM, VibeBoard, prikidka) официальный скилл
shadcn ставится в проект отдельно, вне конвейера.
