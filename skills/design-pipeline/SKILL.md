# Design Pipeline

Тонкий оркестратор. Сам дизайн не делает: связывает три инструмента и встраивает их в стадии
конвейера Покока, чтобы UI получал те же гарантии, что и логика.

- **ux-discovery**: UX-интервью → `docs/discovery.md`
- **impeccable** (4.x): `PRODUCT.md`, `DESIGN.md`, сборка, анти-slop ревью, детектор
- **emil-design-eng**: углублённый motion (easing, springs, тайминги)

Четыре боли, по которым бьёт конвейер: слабый UX, generic-эстетика, разъезжающийся стиль,
сдача вслепую без докрутки.

## Вызов в харнесе

Команды impeccable живут в одном скилле, синтаксис зависит от харнеса:

| Действие | Claude Code | Codex |
|---|---|---|
| команда impeccable | `/impeccable craft hero` | `$impeccable craft hero` |
| другой скилл | Skill tool / `/ux-discovery` | `$ux-discovery` |
| правило интеграции | `CLAUDE.md` | `AGENTS.md` |

Дальше команды записаны без префикса (`impeccable craft`): подставь синтаксис своего харнеса.

## Preflight

Перед первой фазой проверь зависимости по [references/preflight.md](references/preflight.md).
Required (impeccable, ux-discovery) без них конвейер стоит; emil опционален. Чего нет: покажи
команду установки и спроси разрешение. Готово, когда каждая required-зависимость найдена в
папке скиллов текущего харнеса.

## Фазы на стадиях Покока

Каждая фаза врезается в конкретную стадию. Мелкая задача берёт одну фазу, а не весь конвейер
(например, только Ф3 на существующем UI).

### Ф0: UX (рядом с `grill-me` / `wayfinder`)
1. Вызови **ux-discovery** с идеей или PRD. Результат: `docs/discovery.md`.
2. `impeccable init` с вводной «опирайся на docs/discovery.md»: он запишет `PRODUCT.md`
   (аудитория, цель, контекст, голос, ограничения) и спросит только пробелы.
3. На `wayfinder`-карте UX-вопросы становятся тикетами `wayfinder:grilling`.

Готово, когда `PRODUCT.md` лежит в корне и в нём нет пустых секций.

### Ф1: Визуальное направление (до `to-spec`)
Направление выбирается сравнением, а не первой идеей:

1. **Есть живой код** → `impeccable document`: `DESIGN.md` из того, что уже есть.
2. **Нового направления нет** → Pocock **prototype**, UI-ветка: 3+ радикально разных варианта на
   одном маршруте. Референс («хочу как этот сайт») идёт вводной в `impeccable shape` для каждого
   варианта. Пользователь выбирает победителя.
3. Победителя фиксирует `impeccable document` → `DESIGN.md` + токены. Прототипную ветку оставь
   как первоисточник (правило prototype: в main едет только решение).
4. На `wayfinder`-карте это тикет `wayfinder:prototype`.

Готово, когда `DESIGN.md` есть и пользователь явно утвердил направление.

### Ф2: Спека и тикеты (`to-spec`, `to-tickets`)
- Спека ссылается на `PRODUCT.md` и `DESIGN.md` как на источник правды для UI, не копируя их.
- В `to-tickets` первым идёт тикет **«Дизайн-система»** (токены, базовые компоненты, `impeccable
  extract` из прототипа-победителя). Он блокирует каждый UI-тикет: это prefactor из правила
  Покока «make the change easy». Блокировку ставь нативной зависимостью трекера.
- Критерии приёмки UI-тикета включают «`impeccable detect` чистый по затронутым файлам».

### Ф3: Сборка (`implement` / `implement-spec`)
На UI-тикете:
1. Логику и состояние строй через **tdd**, как велит implement.
2. Вёрстку: `impeccable craft <фича>` по `DESIGN.md`.
3. Motion: вызови **emil-design-eng** с конкретным запросом по компонентам этого тикета (easing,
   тайминги до 300ms, spring для drag, `prefers-reduced-motion`). Пустой вызов он отбивает.
   Без emil motion делает `impeccable animate`.

Готово, когда тикет закрывает свои критерии приёмки и `impeccable detect` по его файлам чистый.

### Ф4: Дизайн-ревью (после `code-review`)
`code-review` Покока проверяет Standards и Spec. Ф4 добавляет третью ось, **Design**. Цикл,
лимит **3** итерации:

1. `npx impeccable detect --json <затронутые пути или URL>`: детерминированный проход, 62 правила.
2. `impeccable critique`: иерархия, ясность, эвристический скоринг.
3. `impeccable audit`: a11y, perf, responsive.
4. `impeccable polish`: финальный проход против `DESIGN.md`.
5. `impeccable live`: докрутка в браузере (нужен запущенный dev-server).
6. Применить правки, повторить.

Готово, когда detect чистый и critique/audit не дают находок уровня блокера, либо исчерпан лимит.
Остаток при лимите: отдельные тикеты в трекер, а не молчаливая сдача.

## Граничные случаи
- **Только UI/UX**: backend и доменную логику ведёт обычный конвейер Покока.
- **Нет dev-server**: `live` недоступен, detect и critique работают по файлам и URL.
- **Codex**: impeccable ставит проектный хук в `.codex/hooks.json`; один раз одобри его через `/hooks`.
- **`.impeccable/`**: рабочие файлы impeccable (скриншоты, live-состояние). Эфемерное держи вне
  git: готовый блок `.gitignore` есть в README impeccable, раздел «Keeping .impeccable out of git».
